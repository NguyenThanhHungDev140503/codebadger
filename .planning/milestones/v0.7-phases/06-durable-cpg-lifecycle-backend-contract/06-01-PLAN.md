<objective>
Establish the version-bound durable CPG build lifecycle. Extend `ProjectVersion` schema with state observability fields (`build_status`, `build_metadata`, `updated_at`), enforce DB-level single-active-job deduplication per version in Postgres, wire Git sync to auto-enqueue builds, and drive version status transitions (`queued` -> `building` -> `loading` -> `ready` / `failed`) with sanitized error reporting and cache reuse.
</objective>

<threat_model>
- Threat: Secret Leakage & Stack Trace Exposure in Build Error Metadata.
  Mitigation: All build failure messages stored in `build_metadata` or returned to clients must pass through regex-based error masking (`_mask_text` pattern stripping tokens, credentials, and absolute host paths). Raw exceptions must never be stored on `project_versions.build_metadata`.
- Threat: Duplicate Job Flood / Race Conditions on Build Submissions.
  Mitigation: Create a PostgreSQL partial unique index `idx_jobs_version_active ON jobs(version_id, job_type) WHERE status IN ('queued', 'running') AND version_id IS NOT NULL;` ensuring DB-level single-active-job enforcement per version.
</threat_model>
